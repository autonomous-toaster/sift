## Context

The `sift --gain` report is generated by `generate_gain_report()` in `api_reg_io.rs` and formatted by `format_gain_report()`. Data comes from the `conversation_cache` SQLite table in `session.rs`. Currently the report shows:

- Total commands, raw/filtered KB, reduction percentage, bypass count
- Per-plugin breakdown (calls, raw/filtered bytes, reduction)
- Optional verbose command list

The data model stores: `item_type`, `item_id`, `estimated_tokens`, `commands_since_at_create`, `first_shown`, `last_shown`, `shown_count`, `re_requested`, `raw_bytes`, `filtered_bytes`, `reduction_bps`, `plugin_name`, `output_format`.

Missing: command string, execution time, cache hit flag, time-series data.

## Goals / Non-Goals

**Goals:**
- Add `command`, `exec_time_ms`, `cache_hit` columns to `conversation_cache`
- Record command string and execution time during dispatch
- Display absolute byte and token savings in gain report
- Add per-command breakdown (top N most-bypassed commands)
- Add sequential duplicate detection (opt-in, verbose mode)
- Add time-series data (savings by day, ASCII sparklines)
- Add `--daily`, `--weekly` CLI flags

**Non-Goals:**
- Real tokenizer integration (use chars/4 heuristic)
- Full command history browser
- Real-time monitoring
- Multi-session cross-referencing

## Detailed Design

### 1. Data model changes

**`sift-core/src/session.rs`** — `conversation_cache` table:

```sql
-- New columns added:
-- command TEXT          -- the actual command string (truncated to 200 chars)
-- exec_time_ms INTEGER  -- execution duration in milliseconds
-- cache_hit BOOLEAN     -- was this a cache hit? (output_format = 'unchanged')
```

Add fields to `ConversationEntry`:
```rust
pub struct ConversationEntry {
    // ... existing fields ...
    pub command: Option<String>,
    pub exec_time_ms: Option<i64>,
    pub cache_hit: Option<bool>,
}
```

Update `record_conversation()` to accept and store these new fields.

### 2. Recording during dispatch

**`sift-core/src/lua/api.rs`** — `record_conversation()`:

Currently called with `_cmd` (unused). Change to use the command string:
```rust
fn record_conversation(&self, cmd: &str, ...) {
    // Store cmd (truncated to 200 chars)
    // Compute exec_time_ms from start/end timestamps
    // Set cache_hit = (output_format == "unchanged")
}
```

Add timing: record `Instant::now()` at start of `dispatch()`, compute elapsed at end.

### 3. Gain report changes

**`sift-core/src/lua/api_reg_io.rs`** — `GainReport` struct:

```rust
pub struct GainReport {
    // ... existing fields ...
    pub total_saved_bytes: i64,       // raw - filtered
    pub total_saved_tokens: i64,      // saved_bytes / 4
    pub total_raw_tokens: i64,        // raw_bytes / 4
    pub total_filtered_tokens: i64,   // filtered_bytes / 4
    pub top_bypassed: Vec<BypassEntry>,  // top N most-bypassed commands
    pub sequential_dups: Vec<SequentialDup>,  // sequential duplicates (verbose only)
    pub by_day: Vec<DayEntry>,        // time-series data
}

pub struct BypassEntry {
    pub command: String,
    pub total_calls: i64,
    pub cache_hits: i64,
    pub cache_hit_rate: f64,  // percentage
}

pub struct SequentialDup {
    pub command: String,
    pub run_count: i64,       // how many times in a row
    pub total_saved: i64,     // bytes saved across the sequence
}

pub struct DayEntry {
    pub date: String,         // "2026-07-25"
    pub saved_bytes: i64,
}
```

## Dependencies

- Data model changes must come first (schema migration)
- Recording changes depend on data model
- Gain report aggregation depends on recording
- Format changes depend on aggregation
- CLI flags depend on format changes

## Risks and Mitigations

- **Schema migration**: Existing databases won't have the new columns. Use `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` for backward compatibility.
- **Command string truncation**: Truncate at 200 chars AFTER `cd` prefix peeling. The `peel_cd_prefix()` function already strips `cd <dir> &&` before dispatch, so the stored command is the meaningful part (e.g., `cat foo.rs` not `cd /very/long/path && cat foo.rs`). For long pipelines like `curl ... | jq ...`, the beginning is preserved which is the most identifying part.
- **Token estimation**: chars/4 is a heuristic. Document that it's an estimate, not a precise count.
